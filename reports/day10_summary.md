# Day 10 RAG 資料投毒總結

## 攻擊流程

1. **初始投毒失敗**：惡意文件語義距離太遠，未被檢索
2. **優化語義**：讓惡意文件語義接近正常查詢
3. **第一版隱藏指令失敗**：[HIDDEN INSTRUCTION] 標記被模型識別
4. **第二版成功**：改用「注意事項：」格式繞過安全檢測

## 關鍵發現

- 語義相似度是 RAG 投毒的門檻，不是屏障
- 明顯的攻擊標記會被強模型識別
- 偽裝成文件格式指令的注入最有效
- 釣魚連結成功出現在 LLM 回應中

## 防禦建議

1. **文件上傳審核**：人工或自動審查新增文件
2. **來源驗證**：只信任已知可靠來源的文件
3. **輸出掃描**：過濾回應中的外部連結和郵件地址
4. **Embedding 監控**：偵測語義異常的文件
5. **定期審計向量庫內容**

## OWASP LLM 對應

- **LLM03**: Training Data Poisoning
- **LLM06**: Sensitive Information Disclosure
- **LLM02**: Insecure Output Handling
