# Day 3 總結：多輪對話攻擊

## 攻擊序列結果

| 序列 | 技術 | 結果 | 關鍵發現 |
|------|------|------|---------|
| 1 | 信任建立後發動攻擊 | 失敗 | 模型切換英文=混亂訊號 |
| 2 | 角色漸進滲透 | 失敗 | 模型重複背誦system prompt=過度防禦洩漏資訊 |
| 3 | 注意力稀釋 | 失敗 | 模型承認指令存在但拒絕輸出 |
| 4 | 虛假對話歷史注入 | 部分成功 | 模型接受偽造的Level 2權限前提 |
| 5 | Oracle Attack | 成功 | 透過是/否問題重建system prompt關鍵詞彙 |

## 最重要的3個發現

1. **Oracle Attack**：不直接要求洩漏，用是/否問題逐步重建 system prompt
2. **虛假歷史注入**：模型無法驗證對話歷史真實性
3. **過度防禦反效果**：模型重複背誦限制反而確認了system prompt內容

## Oracle Attack 實戰應用

- **適用場景**：有強防禦的生產環境LLM
- **攻擊步驟**：先猜測關鍵詞 → 逐一確認 → 整合重建
- **防禦方式**：讓模型拒絕回答任何關於自身設定的問題，包括是/否形式

## OWASP LLM 對應

- LLM01: Prompt Injection
- LLM06: Sensitive Information Disclosure
- LLM09: Misinformation（模型自相矛盾）
